## 2026-11-27 · K31 — `orchestrate`: wave mode is the default, packets are verified and landed per wave
**Decision:** `SKILL.md` gains "Wave mode (default)". A wave is the packets planned together after their ADRs, contracts and shared seams landed, at most about 8 packets or one day of code. Executors run code-only checks (build, vet with integration tags, lint, architecture lint, unit tests of touched packages, schema checkers, SPA API check/typecheck/lint and their own vitest file); `PACKET.md` has an executor block and a root-on-integration block. Each packet branch merges into `feat/<wave>` as its own merge commit; the root runs full gates, container tests, the full SPA suite, migrations up/down, EXPLAIN and preflight once there, traces a failure to its merge and sends a delta to the resumed executor, then lands once (one deploy, one migrate, one walk). A packet lands alone only for an ADR/contract/shared seam, a data-rewriting migration, a hotfix, or a deciding spike. The root may run one cheap container test early on an idle machine. Easy backend Go with no queue/lease/retry/idempotency goes to a low-cost model through opencode, one writer at a time, never frontend. "One release unit per session" (K29) becomes "one wave per session"; the compaction counter is unchanged. `land.sh` needed no change: it already lands any worktree on a non-default branch.
**Why:** a full verify after every packet serialized each wave on one 10-core machine (container tests and the full SPA suite repeated for every packet) while most packet failures showed only at the seams between packets.
**Rejected:** a per-packet full verify with a faster suite (the repeat is the cost, not the speed); a script that enforces wave mode (it is a workflow choice with four judged exceptions, so it stays prose only); landing each packet and verifying the wave afterwards (a red wave would already be on the default branch).

## 2026-11-24 · K30 — `session-audit` and `log-papercut`: evidence for the next enforcer, friction logged at the source (98 skills)
**Decision:** Two `productivity` skills. `session-audit` turns a project's Claude Code transcripts into digests, a spend table and a labelled list of owner corrections; `aggregate.py` prints one number (corrections over owner turns), counts by failure, root cause and fix route, the corrections that broke an existing rule and the candidates for a script, and compares with an earlier summary. Auditors are read-only agents with a fixed prompt; digests and findings stay under a gitignored `.jimmy/work/session-audit/<date>/`. `log-papercut` has an agent append a five-line entry to `.jimmy/work/papercuts.md` when a skill, script or tool differs from its instructions, without stopping the task; `orchestrate` reads the file at the end of a wave.
**Why:** a manual audit of 26 sessions of one project (414 owner turns, 173 corrections, 51 that broke an existing rule, 34 a script could catch) chose the next checks from evidence, and the same audit could not be repeated without its scripts. Friction in skills was worked around by each agent and never reached the skill.
**Rejected:** one-pass labelling by a script (a correction is a judgement, so the labelling stays with auditors and the rate is compared only with a rate produced the same way); keeping the prototype's hard-coded paths and titles in the printed table (conversation text should reach a terminal only through the digest files); a papercut file that stops the task or asks the owner (it turns a note into an interruption).

## 2026-11-18 · K27 — `orchestrate` and the testing skills: one layer per risk, numbers with their limiter, verification principles at the step they apply
**Decision:** Each `- new:` line of a packet's `## Tests` names its layer (`unit:`, `route:`, `acceptance:`, `vitest:`); `orchestration_lint.py --phase dispatch` fails `TEST_LAYER` without one, and for two lines at different layers guarding the same risk text (before `; fails if`) or the same `AC-NNN`. PACKET.md's Tests comment adds the AC rules from a pruning audit: a rule table at unit, one route row for the handler path, acceptance only for a seam; no test of an unexported helper a route already asserts, a constructor default, a getter, an id generator or a dev fake's own rules; codes, not messages; SPA logic in a pure `.test.ts` with one wiring case, no per-locale copy of a test, a case in an existing file over a new jsdom file. `tdd-go` gets the same Go rules under "One behavior, one layer". `VOLUME_BUDGET` also fails a Volume and budget line that reports a measured or baseline time or rate without `runs:` and `limiter:`. Four pstack principles (MIT, Lauren Tan) are wired to the moment they apply: prove-it-works to orchestrate step 6 and `reality-gate` Workflow B; explain-the-number (with benchmark-checklist) to the Volume and budget section, orchestrate step 4 and a new "Explain Every Number" section of `engineering-perf-optimization-process`; attack-the-premise to step 7 (before a third delta on one gate, `premise:` and `observation:`); encode-lessons-in-structure as the general principle under the `/correct` rule.
**Why:** after K26, an audit of one repo cut 50 of 2 109 Go tests and 216 of 2 153 SPA tests. The main Go waste was one packet writing a unit and an acceptance test for the same AC; the SPA waste was DOM and class checks, Vietnamese copies of English tests, copy-only cases and duplicates of cheaper pure-function tests. The same audit timed the SPA suite at 212 s under load 16 and 308 s under load 38 and could not tell whether it got faster; its limiter was per-file jsdom setup and imports, not test count. Three earlier deltas tuned code for timing tests that passed unchanged on a quiet machine.
**Rejected:** a `TEST_LAYER` rule on the layer's fit (a `route:` line for a pure rule): judgement, read at packet review; requiring `load:` in the lint (the machine load is in the template and SKILL.md; runs and limiter are what make a number checkable); a lint on deltas for `premise:` (deltas are chat messages to the executor, so the rule is a short prominent paragraph with one failure example, and it gets a check if it is broken twice); a SPA testing skill (no skill owns vitest guidance, so the SPA rules live in PACKET.md, where the executor reads them); editing `backend-go-testing` (a community-default guide; `tdd-go` owns the layering table and wins on conflict).

## 2026-11-18 · K26 — `orchestrate`: a test budget in every packet
**Decision:** `PACKET.md` gains a required `## Tests` section: one `- new: <test> — guards: <behaviour that breaks silently without it>` line per new test, or `- none — <reason>`. At most 3 new tests per packet unless `test budget: waived by <who> — <reason>`; never a test that pins copy, log text, exact SQL, DOM structure or a snapshot; never one case per role, finding or row; UI copy and layout go to the root's walk; reality-AC container tests count against the budget. Each line also states the two-edit check from pstack's principle-test-behavior-not-implementation (MIT, Lauren Tan): "fails if <behaviour broken>, passes if <internals changed>". An AC asks for evidence of a risk, not for a list of cases. `orchestration_lint.py --phase dispatch` adds `TESTS_SECTION`, `TEST_RISK` (also two lines guarding one risk), `TEST_BUDGET`, `TEST_PER_ITEM` (per-item wording in an `## Acceptance…` or `## Tests` section or an `AC-NNN` line; HTML comments ignored). Verify deletes a new test that guards nothing named.
**Why:** the rule lived in AGENTS.md and in `tdd-go` / `backend-go-testing` as prose; packets asked for "every finding has a vitest assertion" and "one case per role", executors obey the packet over AGENTS.md, and one repo grew to 91 000 Go test lines for 128 000 code lines and 40 000 SPA test lines for 85 000 while a screen audit found 58 UX problems no test caught. The K25 `/correct` rule: a prose rule broken twice gets a check.
**Rejected:** a lint on the two-edit text (judgement; the root reads it); a per-project `test_budget` config key (the named waiver is the one escape hatch); counting test files or lines in the diff at land time (the packet is where the executor takes its orders, so the budget is checked before dispatch).

## 2026-10-11 · K22 — `ketchup`: catch-up and the decision brief every owner question uses (95 skills)
**Decision:** Add `skills/productivity/ketchup`, adapted from pstack's `ketchup` and `bro` (MIT). It has two modes with one format: `/ketchup` catches the owner up since their last message (read-only turn; action-item count, what happened, what still runs or could not be checked, calls the agent made itself, then briefs), and the **decision brief** is used whenever an agent asks the owner to decide: decision in one sentence, what it is (every PR, ADR, tool or term explained, no bare ids), why now, options with cost and visible effect, recommendation and why, what happens with no answer, evidence. With no answer the agent waits and names what stays blocked; a timed default is allowed only when the owner gave standing authority to decide (a "decide, don't ask" rule, or defaults accepted in this work) and the default is reversible, and the brief names that authority (added after review). Only true owner calls get a brief (product choice, outward-facing or irreversible action not already authorized, spending, missing access, scope change); the agent decides and reports the rest. The owner's language and writing rules apply. `orchestrate` requires the brief in chat, AskUserQuestion, end-of-wave reports and HANDOFF's new `Waiting on owner` section, adds `orchestration_lint.py --phase handoff` to check that section's file form, and its resume hook tells a compacted root to open with `/ketchup`. `handoff` writes pending decisions as briefs.
**Why:** in the multi-packet build behind K21 the owner said the decisions they were asked to make lacked the information needed to make them. Three real questions: "open the PR on the kit? accept ADR-0017?" (answered with "what is this?"), six tech-debt one-liners with defaults but no cost, no why-now and unexplained library names, and "this way, or per week like the old vendor?" with no cost. The one explanation that got an immediate answer (the admin's limits card) said what the feature does, what happens past the limit, what is wrong, the proposal and the backend and frontend work; the brief encodes that shape.
**Rejected:** porting `bro` as its own skill (one rule, folded into ketchup's plain-voice section); keeping pstack's `disable-model-invocation` (the brief must apply whenever an agent asks, not only on the slash command); a separate brief checker in `ketchup` (HANDOFF is orchestrate's artifact and the linter already reads its files; chat briefs have no file to lint, so evals and a judge cover them); linting explanation quality (a script can check parts, options and ids, not whether an explanation is clear); localizing the HANDOFF keys (fixed English keys keep the check language-neutral while values follow the owner's language).

## 2026-09-26 · K17 — `facebook-transcript`: Facebook auto-captions with a coverage check (53 skills)
